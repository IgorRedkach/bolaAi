# BOLA AI — Architecture

## Overview

BOLA AI is a local-only security analysis agent that runs in Docker. It investigates documentation and log traces to find system vulnerabilities across a broad taxonomy (BOLA, BAC, insecure design, integrity failures, injection, misconfiguration, logging gaps, and more). It combines a local LLM, a vector store for RAG, and an API + chat UI. No outbound traffic is required at runtime; the container can use an ephemeral volume that is wiped when the analysis is done.

## Components

### 1. LLM — Ollama + Pre-baked Model

- **Role:** Analyze artifacts, generate vulnerability hypotheses, and produce verification steps across the full vulnerability taxonomy.
- **Model:** Pre-baked into the Docker image during build. Includes a system prompt and few-shot teaching examples covering BOLA, BAC, insecure design, integrity, injection, misconfiguration, logging, and platform-specific patterns (GraphQL, SOQL, Salesforce, HAR).
- **Deployment:** Runs inside the same container. No internet needed — model weights are baked into the image layer.
- **API:** Ollama exposes `http://localhost:11434` internally; the app calls `/api/chat` for completion.

### 2. Vector DB — ChromaDB

- **Role:** Store embeddings of documentation, knowledge patterns, and training examples for RAG retrieval.
- **Persistence:** Pre-loaded during Docker build with training data (215 examples + knowledge patterns). User documents are added at runtime via auto-ingest.
- **Embeddings:** Generated by a local embedding model (sentence-transformers, also pre-downloaded during build) for fully offline operation.

### 3. Application — FastAPI

- **Role:** Orchestrate ingestion, RAG retrieval, and LLM calls; expose REST API and serve chat UI.
- **Endpoints:**
  - `GET /chat` — Interactive chat UI for natural-language conversation with the agent.
  - `POST /api/chat` — Smart message routing: ingest commands, help, analysis, status.
  - `POST /ingest` — Upload or paste documentation; chunk and embed into ChromaDB.
  - `POST /ingest_shared` — Ingest from the shared Docker docs path (`/shared-docs`).
  - `POST /analyze` — Run vulnerability analysis: RAG context + prompt → LLM → findings + verification.
  - `GET /health` — Health check with auto-ingest/analysis status, chunk counts, and doc sources.
- **CLI:** `python -m bola_ai.cli` for terminal and scripted use.

### 4. Agent / RAG Pipeline

- **Ingest:** Parse docs (text, JSON, YAML, HAR, OpenAPI); chunk by section or token limit; embed; upsert into Chroma. HAR files are preprocessed to extract API-like requests and filter static assets.
- **Analyze:** Build prompt with: (1) system prompt (vulnerability taxonomy), (2) retrieved RAG chunks, (3) user query. LLM returns structured markdown with findings, rationale, and verification steps.
- **Normalization:** Post-processing pipeline (`_normalize_report`) validates and corrects output: path grounding, verification logic correction, spurious content removal, format consistency.
- **Output:** Markdown suitable for auditor reports with concrete, copy-pasteable verification steps.

### 5. Training and Adaptation

- **RAG knowledge base:** Pre-loaded with vulnerability patterns and training examples covering the full taxonomy. Extensible via `data/knowledge/` and `data/training/`.
- **Few-shot teaching:** Modelfile includes MESSAGE pairs covering 15 diverse vulnerability patterns. These are part of every conversation, teaching output format and reasoning.
- **Training data generator:** `src/training/generate_data.py` produces JSONL and RAG chunks from vulnerability scenarios.
- **AI teaching pipeline:** `src/training/ai_teacher_prompts.py` and `scripts/generate_ai_training_tasks.py` create task packs for synthetic training data production with quality gates.

## Docker Strategy

- **All-in-one image:** Single Docker image contains Ollama, the pre-baked model (with few-shot examples), pre-loaded ChromaDB (knowledge base + embeddings), and the FastAPI app. Fully self-contained.
- **Ephemeral volume:** Mount `./data` for runtime Chroma state. Wipe before use (clean state) and after use (no residual sensitive data).
- **Shared docs path:** Mount `./shared_docs` to `/shared-docs` for document intake.
- **Network:** For strict isolation, run with `--network=none`.

## Memory Management (portable local footprint)

Design goal: keep runtime memory usage suitable for portable local environments, with practical guardrails and low-memory test modes. See [MEMORY.md](MEMORY.md).

- **Fake embedder:** `BOLA_AI_FAKE_EMBEDDER=1` skips sentence-transformers for tests.
- **RAG context:** `BOLA_AI_N_CONTEXT` limits retrieved chunks; `BOLA_AI_MAX_CONTEXT_CHARS` caps total context length.
- **Chunking:** Default ~512 chars; HAR preprocessing reduces large captures to API summaries.

## Security and Disposability

- **No telemetry or outbound calls** from the application or LLM at runtime.
- **No persistence of inputs** beyond the container/volume lifecycle.
- **No API keys or cloud credentials required.**
