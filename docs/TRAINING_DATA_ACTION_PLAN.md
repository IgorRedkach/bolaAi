# Training Data Refactor Action Plan (5000 Rich Context Examples)

## Goal

Deliver a high-fidelity dataset and pipeline update that:
- generates realistic user-provided artifacts with hidden security issues,
- produces best-possible grounded expected responses,
- adds explicit analyst reasoning/explanation blocks,
- reaches 5000 rich context examples,
- removes hallucinated/ungrounded findings,
- guarantees taxonomy coverage from `data/knowledge/bola_patterns.md`,
- updates training flow to ingest the new explanation block.

---

## Rules

1. **Realistic artifacts that should be formatted and joined to string**
  - Agent everytime for every example make an analysis: possible industry (random) then possible artifact types (Enforce artifact variation, Use diversified artifact families (OpenAPI, HAR traces, logs, SQL DDL, architecture docs, schemas, settings exports, roles explanations, user documentation, pure code, runbooks, mixed-document sets)) then of possible system architecture (think about it and make it the best accurate possible with a lot of details, you can generate temporary documents) and then about possible risks/security gaps for selected architecture and then about possible volume of documentation

2. **Best expected response per context**
   - Agent should analyse request context as an independant agent that got this request and give the best response it gen make after good analyse.

3. **Add explanation section**
   - Add `analysis_explanation` block describing reasoning path and evidence-to-finding decisions.

## Progress tracker:
[ ] **Generate 5000 rich examples**
   - Produce at least 5000 training rows generated by rules above 1-3 (Each training row should include:
- `id`
- `artifacts_context` (raw user-like artifacts)
- `target_patterns` (one or more labels from taxonomy)
- `expected_response` (best grounded tool response)
- `analysis_explanation` (how context was analyzed and decisions were made)
)

[ ] **Hallucination/ungrounded finding cleanup**
   - check all the generated data for hallucinations or ungrounded evidences in context or response or explanation; Agent should make analyse of every example separatelly without bias; fix or drop failing examples.

[ ] **Taxonomy class coverage validation**
   - Build class/subclass coverage matrix and generate test examples for missing classes.

[x] **Refactor training process for explanation block**
   - Update data schema, dataset build scripts, and training prep to include explanation text.


## Exit Criteria

Plan is considered complete only when:
- all progress tracker points implemented
