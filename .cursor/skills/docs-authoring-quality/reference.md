# Documentation Style Reference

## Principles

- Be concise and scannable.
- Frame content around user tasks.
- Use progressive disclosure for advanced details.
- Prefer real examples over abstract text.
- Snippets must be copy-pasteable.
- State prerequisites before steps.
- Keep one topic per page.
- Link related docs inline instead of repeating content.
- Show expected output after each important step.
- Keep terminology stable.

## Tone

- Developer-to-developer, clinical and direct.
- No patronizing explanation tables.
- No personality copy ("Let's dive in", "Pro tip", emojis, etc.).
- Prefer inline guidance over repeated heavy callout blocks.

## Page and Heading Rules

- Page title should match sidebar title.
- Avoid frontmatter `description`.
- Keep headings plain and direct, not narrative.
- Use TOC-friendly short headings.

## Example Rules

- Use realistic paths, requests, and prompts.
- Include non-obvious syntax/flags when examples are present.
- Skip low-value examples that merely restate prose.
