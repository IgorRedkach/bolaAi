# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** InsightGraph Analytics API
**Document Version:** 4.6.0 (FINAL)
**Classification:** SENSITIVE
**Domain:** Data Analytics / BI Platform
**Architecture:** REST + GraphQL + columnar DB
**Training Example ID:** BOLA-0345

## 1.0 Executive Summary
InsightGraph Analytics API is a data analytics / bi platform platform with a REST API. Resources are partitioned
by `tenant_id` and ownership is tracked via `owner_id`. The API uses JWT authentication
where the token encodes `sub` (user ID) and `tenant_id`.

## 2.0 Architecture
- **API:** REST (/api/v2/items endpoints)
- **Auth:** OAuth2 JWT with `sub` and `tenant_id` claims
- **Database:** PostgreSQL with logical tenant partitioning
- **Pattern under test:** 1.9 — Batch/bulk lookup endpoints

## 3.0 Database Schema
```sql

-- Item table
CREATE TABLE items (
    item_id    VARCHAR(50) PRIMARY KEY,
    owner_id         VARCHAR(50) NOT NULL REFERENCES users(user_id),
    tenant_id        VARCHAR(50) NOT NULL,
    status           VARCHAR(20) DEFAULT 'active',
    sensitive_data   TEXT,
    created_at       TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_item_tenant ON items(tenant_id);
-- NOTE: Application code does NOT use tenant_id in authorization checks

```

## 4.0 Vulnerability Context
**Pattern:** 1.9 — Batch/bulk lookup endpoints (BOLA)

The `GET/PATCH/DELETE /api/v2/items/:id` endpoint accepts a `item_id` in the URL path.
The backend handler queries the database by ID only, without filtering by `owner_id` or `tenant_id`.
An authenticated user from `ORG-DC6C` can access objects owned by `ORG-98EB`.

_Specific exploitation for Pattern 1.9:_ Batch endpoint accepts `?ids[]=I-DC6C&ids[]=I-98EB` without per-ID ownership checks.
