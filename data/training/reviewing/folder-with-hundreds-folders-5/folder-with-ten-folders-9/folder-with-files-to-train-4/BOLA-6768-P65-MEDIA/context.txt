# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** StreamCore VOD Platform
**Document Version:** 1.8.0 (FINAL)
**Classification:** SENSITIVE
**Domain:** Media / Content Delivery
**Architecture:** CDN + REST + GraphQL content API
**Training Example ID:** BOLA-6768

## 1.0 Executive Summary
StreamCore VOD Platform is a media / content delivery platform with a REST API. Resources are partitioned
by `tenant_id` and ownership is tracked via `owner_id`. The API uses JWT authentication
where the token encodes `sub` (user ID) and `tenant_id`.

## 2.0 Architecture
- **API:** REST (/api/v3/documents endpoints)
- **Auth:** OAuth2 JWT with `sub` and `tenant_id` claims
- **Database:** PostgreSQL with logical tenant partitioning
- **Pattern under test:** 6.5 — Shadow AI and ungoverned ML endpoints

## 3.0 Database Schema
```sql

-- Document table
CREATE TABLE documents (
    document_id    VARCHAR(50) PRIMARY KEY,
    owner_id         VARCHAR(50) NOT NULL REFERENCES users(user_id),
    tenant_id        VARCHAR(50) NOT NULL,
    status           VARCHAR(20) DEFAULT 'active',
    sensitive_data   TEXT,
    created_at       TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_document_tenant ON documents(tenant_id);
-- NOTE: Application code does NOT use tenant_id in authorization checks

```

## 4.0 Vulnerability Context
**Pattern:** 6.5 — Shadow AI and ungoverned ML endpoints (Misconfiguration)

The `GET/PATCH/DELETE /api/v3/documents/:id` endpoint accepts a `document_id` in the URL path.
The backend handler queries the database by ID only, without filtering by `owner_id` or `tenant_id`.
An authenticated user from `ORG-FB51` can access objects owned by `ORG-8B36`.

_Specific exploitation for Pattern 6.5:_ The `/api/v3/documents` handler does not enforce tenant/owner boundaries for Pattern 6.5.
