# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** SkyPort Global Distribution
**Document Version:** 2.6.0 (FINAL)
**Classification:** SENSITIVE
**Domain:** Travel / GDS
**Architecture:** XML-based GDS + REST + GraphQL
**Training Example ID:** BOLA-6467

## 1.0 Executive Summary
SkyPort Global Distribution is a travel / gds platform with a REST API. Resources are partitioned
by `tenant_id` and ownership is tracked via `owner_id`. The API uses JWT authentication
where the token encodes `sub` (user ID) and `tenant_id`.

## 2.0 Architecture
- **API:** REST (/api/v3/nodes endpoints)
- **Auth:** OAuth2 JWT with `sub` and `tenant_id` claims
- **Database:** PostgreSQL with logical tenant partitioning
- **Pattern under test:** 2.2 — Metadata/attribute side-channel

## 3.0 Database Schema
```sql

-- Node table
CREATE TABLE nodes (
    node_id    VARCHAR(50) PRIMARY KEY,
    owner_id         VARCHAR(50) NOT NULL REFERENCES users(user_id),
    tenant_id        VARCHAR(50) NOT NULL,
    status           VARCHAR(20) DEFAULT 'active',
    sensitive_data   TEXT,
    created_at       TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_node_tenant ON nodes(tenant_id);
-- NOTE: Application code does NOT use tenant_id in authorization checks

```

## 4.0 Vulnerability Context
**Pattern:** 2.2 — Metadata/attribute side-channel (BAC)

The `GET/PATCH/DELETE /api/v3/nodes/:id` endpoint accepts a `node_id` in the URL path.
The backend handler queries the database by ID only, without filtering by `owner_id` or `tenant_id`.
An authenticated user from `ORG-62D0` can access objects owned by `ORG-A87B`.

_Specific exploitation for Pattern 2.2:_ The `/api/v3/nodes` handler does not enforce tenant/owner boundaries for Pattern 2.2.
