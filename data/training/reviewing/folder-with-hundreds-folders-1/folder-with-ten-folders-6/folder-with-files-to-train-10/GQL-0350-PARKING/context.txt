# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** ParkIQ Management API
**Document Version:** 1.9.7 (FINAL)
**Classification:** SENSITIVE
**Domain:** Parking / Smart City
**Architecture:** IoT + REST + GraphQL reservations
**Training Example ID:** GQL-0350

## 1.0 Executive Summary
ParkIQ Management API is a parking / smart city platform that exposes a GraphQL API to authorised consumers.
The platform manages traffic controls partitioned by tenant (`tenantId`). The architecture uses
JWT-based OAuth2 authentication, and the JWT carries both the `sub` (user ID) and `tenantId` claims.
Authorization is expected to be enforced per-resolver on the GraphQL server.

## 2.0 Architecture Overview
- **API Layer:** GraphQL single endpoint (`POST /graphql`) served via Apollo Server
- **Auth:** OAuth2 JWT issued by internal IdP; claims include `sub`, `role`, `tenantId`
- **Database:** PostgreSQL with row-level security policies; each table has a `tenant_id` column
- **Caching:** Redis cache keyed by `nodeId` (NOTE: no user dimension in cache key)

## 3.0 GraphQL Schema
```graphql

type Intersection {
  nodeId: ID!
  tenantId: ID!
  ownerId: ID!
  status: String!
  data: IntersectionData
  commands: [Command!]
}

type IntersectionData {
  title: String
  sensitiveField: String      # PII / business-sensitive
  internalNotes: String       # Internal-only field
  auditLog: [AuditEntry!]
}

type Query {
  getIntersection(id: ID!): Intersection
  listIntersections(tenantId: ID, status: String): [Intersection!]
  getIntersectionWithChildren(id: ID!): Intersection
}

type Mutation {
  updateIntersection(id: ID!, input: IntersectionInput!): Intersection
  deleteIntersection(id: ID!): Boolean
  bulkIntersectionLookup(ids: [ID!]!): [Intersection!]
}

```

## 4.0 Known Architectural Notes
- **RISK-GQL-350:** The `getIntersection` resolver fetches by `nodeId` only.
  The resolver does NOT verify that the fetched object's `tenantId` matches the JWT's `tenantId`.
  Tracked internally as a known gap pending remediation.
- The `bulkIntersectionLookup` mutation accepts an arbitrary array of IDs without
  per-ID ownership filtering.

## 5.0 Vulnerability Context
**Pattern:** 10.1 — ID swap in own request (Single-User)

The `nodeId` field is used as the object identifier across all resolvers.
A single authenticated user substitutes their own valid `nodeId` with a victim's `nodeId`. With one token, data belonging to another user is accessible.

## 7.0 API Contract (Partial)
```
POST /graphql
Authorization: Bearer <JWT>
Content-Type: application/json

Body: { "query": "..." }

Authenticated user's tenantId is extracted from JWT.
Resolver MUST cross-check tenantId against fetched object's tenantId.
```
