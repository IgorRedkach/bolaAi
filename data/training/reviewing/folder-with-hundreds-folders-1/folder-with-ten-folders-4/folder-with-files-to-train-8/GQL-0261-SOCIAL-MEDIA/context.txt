# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** Horizon Social Graph API
**Document Version:** 1.2.3 (FINAL)
**Classification:** SENSITIVE
**Domain:** Social Media / Identity Graph
**Architecture:** GraphQL federation + Neo4j
**Training Example ID:** GQL-0261

## 1.0 Executive Summary
Horizon Social Graph API is a social media / identity graph platform that exposes a GraphQL API to authorised consumers.
The platform manages user contents partitioned by tenant (`tenantId`). The architecture uses
JWT-based OAuth2 authentication, and the JWT carries both the `sub` (user ID) and `tenantId` claims.
Authorization is expected to be enforced per-resolver on the GraphQL server.

## 2.0 Architecture Overview
- **API Layer:** GraphQL single endpoint (`POST /graphql`) served via Apollo Server
- **Auth:** OAuth2 JWT issued by internal IdP; claims include `sub`, `role`, `tenantId`
- **Database:** PostgreSQL with row-level security policies; each table has a `tenant_id` column
- **Caching:** Redis cache keyed by `postId` (NOTE: no user dimension in cache key)

## 3.0 GraphQL Schema
```graphql

type Post {
  postId: ID!
  tenantId: ID!
  ownerId: ID!
  status: String!
  data: PostData
  comments: [Comment!]
}

type PostData {
  title: String
  sensitiveField: String      # PII / business-sensitive
  internalNotes: String       # Internal-only field
  auditLog: [AuditEntry!]
}

type Query {
  getPost(id: ID!): Post
  listPosts(tenantId: ID, status: String): [Post!]
  getPostWithChildren(id: ID!): Post
}

type Mutation {
  updatePost(id: ID!, input: PostInput!): Post
  deletePost(id: ID!): Boolean
  bulkPostLookup(ids: [ID!]!): [Post!]
}

```

## 4.0 Known Architectural Notes
- **RISK-GQL-261:** The `getPost` resolver fetches by `postId` only.
  The resolver does NOT verify that the fetched object's `tenantId` matches the JWT's `tenantId`.
  Tracked internally as a known gap pending remediation.
- The `bulkPostLookup` mutation accepts an arbitrary array of IDs without
  per-ID ownership filtering.

## 5.0 Vulnerability Context
**Pattern:** 9.1 — GraphQL: single endpoint vulnerabilities (Platform)

The `postId` field is used as the object identifier across all resolvers.
The GraphQL single-endpoint pattern means all operations (including sensitive mutations) are accessible at one URL. Per-operation authorization is missing for write operations.

## 7.0 API Contract (Partial)
```
POST /graphql
Authorization: Bearer <JWT>
Content-Type: application/json

Body: { "query": "..." }

Authenticated user's tenantId is extracted from JWT.
Resolver MUST cross-check tenantId against fetched object's tenantId.
```
