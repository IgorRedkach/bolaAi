# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** RealmForge Game API
**Document Version:** 4.7.8 (FINAL)
**Classification:** SENSITIVE
**Domain:** Gaming / MMO Backend
**Architecture:** WebSocket + REST + GraphQL economy
**Training Example ID:** GQL-0132

## 1.0 Executive Summary
RealmForge Game API is a gaming / mmo backend platform that exposes a GraphQL API to authorised consumers.
The platform manages game assets partitioned by tenant (`tenantId`). The architecture uses
JWT-based OAuth2 authentication, and the JWT carries both the `sub` (user ID) and `tenantId` claims.
Authorization is expected to be enforced per-resolver on the GraphQL server.

## 2.0 Architecture Overview
- **API Layer:** GraphQL single endpoint (`POST /graphql`) served via Apollo Server
- **Auth:** OAuth2 JWT issued by internal IdP; claims include `sub`, `role`, `tenantId`
- **Database:** PostgreSQL with row-level security policies; each table has a `tenant_id` column
- **Caching:** Redis cache keyed by `characterId` (NOTE: no user dimension in cache key)

## 3.0 GraphQL Schema
```graphql

type Character {
  characterId: ID!
  tenantId: ID!
  ownerId: ID!
  status: String!
  data: CharacterData
  inventorys: [Inventory!]
}

type CharacterData {
  title: String
  sensitiveField: String      # PII / business-sensitive
  internalNotes: String       # Internal-only field
  auditLog: [AuditEntry!]
}

type Query {
  getCharacter(id: ID!): Character
  listCharacters(tenantId: ID, status: String): [Character!]
  getCharacterWithChildren(id: ID!): Character
}

type Mutation {
  updateCharacter(id: ID!, input: CharacterInput!): Character
  deleteCharacter(id: ID!): Boolean
  bulkCharacterLookup(ids: [ID!]!): [Character!]
}

```

## 4.0 Known Architectural Notes
- **RISK-GQL-132:** The `getCharacter` resolver fetches by `characterId` only.
  The resolver does NOT verify that the fetched object's `tenantId` matches the JWT's `tenantId`.
  Tracked internally as a known gap pending remediation.
- The `bulkCharacterLookup` mutation accepts an arbitrary array of IDs without
  per-ID ownership filtering.

## 5.0 Vulnerability Context
**Pattern:** 10.5 — Draft / non-published resource access (Single-User)

The `characterId` field is used as the object identifier across all resolvers.
The resolver handling `characterId` does not enforce ownership or tenancy boundaries, enabling Pattern 10.5 exploitation.

## 7.0 API Contract (Partial)
```
POST /graphql
Authorization: Bearer <JWT>
Content-Type: application/json

Body: { "query": "..." }

Authenticated user's tenantId is extracted from JWT.
Resolver MUST cross-check tenantId against fetched object's tenantId.
```
