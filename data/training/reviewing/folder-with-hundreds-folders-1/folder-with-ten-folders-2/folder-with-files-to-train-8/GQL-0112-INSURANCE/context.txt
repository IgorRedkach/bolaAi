# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** ClaimsFlow Underwriting API
**Document Version:** 2.1.2 (FINAL)
**Classification:** SENSITIVE
**Domain:** Insurance / Claims Processing
**Architecture:** SOAP + REST + GraphQL facade
**Training Example ID:** GQL-0112

## 1.0 Executive Summary
ClaimsFlow Underwriting API is a insurance / claims processing platform that exposes a GraphQL API to authorised consumers.
The platform manages claim records partitioned by tenant (`tenantId`). The architecture uses
JWT-based OAuth2 authentication, and the JWT carries both the `sub` (user ID) and `tenantId` claims.
Authorization is expected to be enforced per-resolver on the GraphQL server.

## 2.0 Architecture Overview
- **API Layer:** GraphQL single endpoint (`POST /graphql`) served via Apollo Server
- **Auth:** OAuth2 JWT issued by internal IdP; claims include `sub`, `role`, `tenantId`
- **Database:** PostgreSQL with row-level security policies; each table has a `tenant_id` column
- **Caching:** Redis cache keyed by `claimId` (NOTE: no user dimension in cache key)

## 3.0 GraphQL Schema
```graphql

type Claim {
  claimId: ID!
  tenantId: ID!
  ownerId: ID!
  status: String!
  data: ClaimData
  documents: [Document!]
}

type ClaimData {
  title: String
  sensitiveField: String      # PII / business-sensitive
  internalNotes: String       # Internal-only field
  auditLog: [AuditEntry!]
}

type Query {
  getClaim(id: ID!): Claim
  listClaims(tenantId: ID, status: String): [Claim!]
  getClaimWithChildren(id: ID!): Claim
}

type Mutation {
  updateClaim(id: ID!, input: ClaimInput!): Claim
  deleteClaim(id: ID!): Boolean
  bulkClaimLookup(ids: [ID!]!): [Claim!]
}

```

## 4.0 Known Architectural Notes
- **RISK-GQL-112:** The `getClaim` resolver fetches by `claimId` only.
  The resolver does NOT verify that the fetched object's `tenantId` matches the JWT's `tenantId`.
  Tracked internally as a known gap pending remediation.
- The `bulkClaimLookup` mutation accepts an arbitrary array of IDs without
  per-ID ownership filtering.

## 5.0 Vulnerability Context
**Pattern:** 1.2 — Related or linked resources (BOLA)

The `claimId` field is used as the object identifier across all resolvers.
The resolver handling `claimId` does not enforce ownership or tenancy boundaries, enabling Pattern 1.2 exploitation.

## 7.0 API Contract (Partial)
```
POST /graphql
Authorization: Bearer <JWT>
Content-Type: application/json

Body: { "query": "..." }

Authenticated user's tenantId is extracted from JWT.
Resolver MUST cross-check tenantId against fetched object's tenantId.
```
