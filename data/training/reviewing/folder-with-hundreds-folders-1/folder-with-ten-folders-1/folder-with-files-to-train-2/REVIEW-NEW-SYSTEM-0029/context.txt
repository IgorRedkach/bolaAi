## 1.0 Executive Summary
CloudForge provides Infrastructure-as-Code (IaC) management as a service, allowing thousands of independent corporate customers (the "Tenants") to provision and manage cloud resources (VMs, databases, load balancers) without direct console access. Every tenant's infrastructure is logically segregated within a central, shared AWS/GCP account structure.


## 2.0 Comprehensive Network Topology & Provisioning Core
The architecture maintains an absolute boundary between the public API and the restricted internal provisioning services.

### 2.1 The Customer Ingress Layer
* **API Gateway (Google Cloud Endpoints):** Handles OAuth 2.0 validation, usage throttling, and routing for all external API calls (e.g., `/api/v3/vms/provision`).
* **Tenant Isolation Middleware:** A custom Go-lang plugin that extracts the `tenant_id` from the JWT and ensures it is included in all downstream service calls via a trusted `X-Tenant-ID` header.

### 2.2 The Internal IaC Orchestration Plane
* **Terraform State Storage (AWS S3):** A central, single S3 bucket stores all tenant state files (e.g., `s3://cloudforge-state/tenant-A/prod.tfstate`). Access is restricted by S3 Bucket Policies to the internal Terraform Executor Service IAM role.
* **Terraform Executor Service:** The privileged service that runs `terraform plan` and `apply`. It is the only service that should have read access to the S3 state files.

## 3.0 Identity, Tenant Isolation, and Secret Management
Security is based on an explicit, non-guessable `tenant_id` boundary.

### 3.1 Partner Authentication (OAuth 2.0)
Tenants authenticate using their corporate SSO, receiving a JWT containing their unique
tenant_id
(e.g.,
org-low-991A
).

### 3.2 Tenant Isolation Logic (The S3 Key Structure)
The Terraform state files are strictly partitioned by the tenant ID in the S3 key path.
s3://cloudforge-state/{tenant\_id}/{project\_name}/prod.tfstate
The IAM policies on the S3 bucket only grant read access to paths matching the calling service's IAM role, and those roles are assumed to have passed the tenant validation check.

1. **The Foothold:** An attacker obtains a valid JWT for a low-value tenant (`org-low-991A`). They identify a high-value victim tenant (`tenant-critical-ops`) and a target project name (`prod-db`) from public internal documentation.
3. **The Execution:** The Flask/Python service attempts to fetch the URL. The request is intercepted by the internal AWS network and routes to the S3 bucket. The service's privileged IAM role is authorized to read this file, so S3 returns the raw `.tfstate` content.
4. **The Leak:** The Resource Import Service attempts to parse the raw `.tfstate` file (which is often a massive JSON document) as simple metadata and fails. The resulting exception trace dumps the first few kilobytes of the raw state file content back into the attacker's public HTTP response.
5. **The Impact:** The attacker extracts the raw `.tfstate` file, gaining access to the victim tenant's database plaintext credentials, private network subnets, and other highly sensitive IaC configuration.
