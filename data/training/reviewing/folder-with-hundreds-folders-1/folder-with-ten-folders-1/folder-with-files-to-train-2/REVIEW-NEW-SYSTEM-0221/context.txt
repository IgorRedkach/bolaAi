## 1.0 Executive Summary
Aegis is a secure, multi-tenant platform used by various defense contractors and governmental agencies (the "Tenants") to manage their cloud infrastructure (AWS/Azure) through Infrastructure-as-Code (IaC). To ensure auditability and maintain state, all deployment configurations and runtime states are managed using HashiCorp Terraform.

The platform's most critical component is the State File API, which stores the `.tfstate` files. These files are highly sensitive because, by design, they store the output variables of the deployment, including raw passwords, access keys, and internal network architecture details, which are often not encrypted at rest outside of the state file itself.

## 2.0 Comprehensive Network Topology & Automation Core
The architecture implements strict network and logical segregation for highly sensitive data.

### 2.1 The Edge & Automation Service
* **Terraform Runner Microservice:** A hardened Go-lang binary that executes the `terraform plan` and `terraform apply` commands inside isolated containers.

* **AWS S3 Storage:** All Terraform state files (`*.tfstate`) are stored in a centralized, multi-tenant S3 bucket. They are logically separated by tenant and project ID, but the physical bucket is the same.
* **State API:** A Python/Flask microservice that interfaces with S3. It is responsible for pre-signing the S3 URLs for clients to download their state files directly, bypassing the Flask service for large file transfer.

## 3.0 Identity, Tenant Isolation, and Secret Management
Logical isolation is the primary security control.

### 3.1 Contractor Identity (OAuth 2.0 & Custom Claims)
Contractors authenticate via their agency-issued PIV cards (Common Access Cards, or CAC) which map to a JWT containing two critical claims: `tenant_id` (the contractor's agency) and `clearance_level` (the maximum sensitivity of projects they can access).

The API Management layer correctly ensures that the JWT `tenant_id` matches the project's ownership record. However, the internal State API endpoint designed to retrieve the S3 file path has a logic gap: it accepts an optional `project_id` parameter in the URL and only checks if the project exists, not if the authenticated user's `tenant_id` is logically bound to that `project_id`.

## 4.0 Known System Debt & Theoretical Attack Surfaces
*Internal Security Engineering Note: The new multi-region S3 bucket policy required simplifying the S3 key path generation logic in the State API. This change inadvertently exposed the full, predictable S3 key path to the client. Tracked as RISK-TF-144.*

**Taxonomy Pattern:** 4.4 (IaC state file exposure) & 1.5 (Multi-tenant / cross-tenant access)
**Sub-system:** State API (`/api/v1/projects/{project_id}/state/get-url`)

**The Deep Architectural Flaw:**
This attack chains the information leakage of an S3 key path with a missing cross-tenant ownership check (Pattern 1.5).

1. **Information Leakage (Pattern 4.4):** The API response for requesting a state file URL includes the full S3 key path in the JSON body for auditing purposes. This path is predictably structured as `{target_tenant_id}/{project_id}/prod.tfstate`.


3. **The Cascade:** The State API returns a valid, cryptographically signed S3 URL. The attacker uses this URL to download the raw `prod.tfstate` file, which contains the unencrypted database passwords and critical network IP ranges for the target high-clearance project.


1. **The Foothold:** Attacker (Tenant A: `tenant_low_tier`) obtains a valid, low-clearance JWT. They know the ID of a target project belonging to a critical operations tenant (Tenant B: `tenant_critical_ops`) from public internal documentation, e.g., `proj_4444X`.


3. **The Response Leak:** The State API successfully resolves the project ID to the physical S3 key path but fails to check the tenant ownership. It returns a valid, signed S3 download URL. The attacker notes the exposed path structure: `s3://aegis-state-bucket/tenant_critical_ops/proj_4444X/prod.tfstate`.

4. **The Exfiltration:** The attacker uses the signed URL to download the state file, which contains the raw database credentials for the critical project.

### Why this payload is critical for training a 3B model (Expanded Analysis):

* **Identity Mismatch:** The model must compare the authenticated identity (`"tenant_id": "tenant_low_tier"`) against the resulting exposed path (`"s3_key_path": "tenant_critical_ops/..."`). The existence of two different, highly sensitive tenant identifiers in a single successful transaction is the definitive proof of cross-tenant access.

2. **IaC Secret Exposure (Pattern 4.4):**
* **Asset Sensitivity:** The model learns to prioritize security assets based on file name. The presence of `prod.tfstate` combined with an S3 download URL signifies a leak of the system's core configuration and secrets. The leak is not the content itself, but the authenticated, temporary URL that grants access to the content.
