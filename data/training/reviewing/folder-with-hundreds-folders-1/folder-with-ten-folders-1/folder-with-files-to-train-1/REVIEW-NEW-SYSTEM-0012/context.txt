## 1.0 Executive Summary
AquaGrid is a multi-tenant, cloud-native Advanced Metering Infrastructure (AMI) platform used by over 150 local municipalities and county water districts across North America. The platform replaces manual water meter reading by deploying IoT-enabled "Smart Meters" to residential and commercial properties. 

These smart meters report hourly water consumption data via a Low-Power Wide-Area Network (LPWAN) such as LoRaWAN or NB-IoT. The AquaGrid platform aggregates this data for automated billing, detects residential pipe leaks, and critically, provides municipalities with the ability to remotely actuate physical shut-off valves at the meter (e.g., for non-payment or emergency main breaks) via a centralized GraphQL API.

## 2.0 Comprehensive Network Topology & IoT Edge
The architecture bridges low-power physical IoT endpoints with a high-availability multi-tenant cloud.

### 2.1 The Physical IoT Edge (Meters & Concentrators)
* **Smart Endpoints:** Battery-powered ultrasonic water meters with embedded LoRaWAN radios and motorized ball valves for remote shut-off.
* **Neighborhood Concentrators:** Pole-mounted gateways that aggregate LoRaWAN packets from thousands of local meters and backhaul the traffic to the AWS cloud via 5G cellular connections.

### 2.2 The Cloud Ingress & API Router
* **GraphQL Federation:** The core web interface for municipal administrators operates on a modern Apollo GraphQL Supergraph. It stitches together multiple underlying microservices (Billing, Telemetry, and Device Control).
* **Ingress Firewall:** AWS WAF is configured to block standard SQLi/XSS, but relies on the underlying application logic for complex rate limiting and authorization.

### 2.3 The SCADA / Device Control Microservice
* **Valve Actuation Service:** A highly restricted Go-lang microservice responsible for translating GraphQL mutation requests (e.g., `setValveState(CLOSE)`) into proprietary binary payloads that are queued and pushed down to the physical neighborhood concentrators.

## 3.0 Multi-Tenant Identity and Access Management (IAM)
Because AquaGrid serves 150 different municipalities (each acting as an isolated tenant), identity boundary enforcement is the most critical security control in the platform.

### 3.1 Delegated Authentication (SAML 2.0 & OAuth2)
To accommodate the IT requirements of different city governments, AquaGrid supports "Bring Your Own Identity" (BYOI). 
* A city IT administrator can configure AquaGrid to trust their specific Microsoft Entra ID (Azure AD) or Okta tenant.
* When a municipal worker logs in, they are redirected to their city's login page. Upon success, the identity provider issues a JWT signed by the city's private key.
* The AquaGrid API Gateway validates the JWT signature using the public JWKS (JSON Web Key Set) endpoint registered for that specific municipality.

### 3.2 Tenant Isolation Logic
The GraphQL router extracts the `tenant_id` and `role` from the verified JWT. Every subsequent database query and device command must strictly enforce that the user is only interacting with meters belonging to their specific `tenant_id`.

## 4.0 Known System Debt & Theoretical Attack Surfaces
*Internal Security Engineering Note: The recent GraphQL migration (Epic: GRPH-202) vastly improved frontend load times but introduced complex query depth and batching challenges that have not been fully modeled for denial-of-service implications. Tracked as RISK-CITY-019.*

**Taxonomy Pattern:** 2.4 (Third-party token/SSO misconfiguration) & 5.3 (GraphQL alias batching/DoS)
**Sub-system:** GraphQL API Gateway & Auth Middleware (`/graphql`)

**The Deep Architectural Flaw:**
This attack relies on a catastrophic failure in the SSO validation logic, amplified by a GraphQL-specific attack vector.
1.  **The SSO Issuer Flaw (Pattern 2.4):** The API Gateway validates that the incoming JWT is cryptographically signed. However, it blindly trusts the `iss` (Issuer) URL provided *inside the token header* to fetch the public verification key (JWKS), rather than strictly checking the issuer against a hardcoded whitelist of approved municipal tenants. This allows an attacker to spin up their own free Auth0 account, generate a valid JWT, and trick the AquaGrid gateway into validating it.
2.  **The GraphQL Alias Flaw (Pattern 5.3):** The `ValveActuation` subgraph allows administrators to remotely shut off a water meter. While the WAF limits users to 10 HTTP requests per minute to prevent mass-shutoffs, it does not inspect the GraphQL payload. An attacker can use GraphQL "Aliases" to pack thousands of distinct `setValveState` mutations into a *single* HTTP POST request. 

1.  **Forging the Identity:** The attacker creates a free developer account on Okta. They mint a JWT claiming the role `city_admin` and inject the target municipality's ID (`tenant_id: "city_of_chicago_01"`). Because of the Issuer Confusion flaw, the AquaGrid gateway downloads the attacker's public key, verifies the forged token, and grants the attacker full administrative rights over Chicago's water grid.
2.  **Bypassing Rate Limits via Batching:** The attacker wants to shut off water to an entire ZIP code. They know the WAF will block them if they send 5,000 separate HTTP requests. 
3.  **The Strike:** The attacker crafts a single GraphQL HTTP POST payload containing 5,000 aliased mutations (e.g., `cmd1: setValveState(meterId: "MTR-1", state: CLOSED)`, `cmd2: setValveState(meterId: "MTR-2", state: CLOSED)`, etc.).
4.  **The Cascade:** The gateway parses the single HTTP request (bypassing the WAF), accepts the forged token, and the GraphQL engine resolves all 5,000 mutations asynchronously. Within seconds, the command queue floods the LPWAN network, and 5,000 residential water valves physically rotate shut.

## 6.0 The Flawed Implementation (Node.js SSO Middleware)

```javascript
const jwt = require('jsonwebtoken');
const jwksClient = require('jwks-rsa');

async function requireCityAdminAuth(req, res, next) {
    const token = req.headers.authorization?.split(' ')[1];
    if (!token) return res.status(401).send("No token provided");

    try {
        // FLAW 1: Decoding the unverified token to extract the 'iss' (Issuer)
        // The attacker completely controls this value.
        const decodedUnverified = jwt.decode(token, { complete: true });
        const dynamicIssuerUrl = decodedUnverified.payload.iss; 

        // BUG-CITY-019: The code FAILS to verify if `dynamicIssuerUrl` exists in the 
        // `tenants.sso_issuer_url` database column BEFORE fetching the keys.
        
        // FLAW 2: The server makes an outbound HTTP request to the attacker's URL 
        // to download the public key used to verify the token.
        const client = jwksClient({
            jwksUri: `${dynamicIssuerUrl}/.well-known/jwks.json` // Points to attacker's Auth0
        });

        const key = await client.getSigningKey(decodedUnverified.header.kid);
        const signingKey = key.getPublicKey();

        // FLAW 3: The token signature is verified against the ATTACKER'S public key.
        // It passes perfectly. The attacker is now authenticated as a City Admin.
        const verifiedPayload = jwt.verify(token, signingKey);
        
        // Context is populated with the attacker's injected tenant_id ("city_of_chicago_01")
        req.userContext = verifiedPayload; 
        next();

    } catch (err) {
        return res.status(403).send("Invalid Token");
    }
}
```

## 7.0 GraphQL Schema & Alias Contract (The Attack Vector)

### 7.1 The GraphQL Schema Definition
```graphql
enum ValveState {
    OPEN
    CLOSED
}

type Mutation {
    # Changes the physical state of a remote smart meter valve
    setValveState(meterId: ID!, targetState: ValveState!): ValveStatusUpdate!
}

type ValveStatusUpdate {
    meterId: ID!
    status: String!
    queuedAt: String!

```

### 7.2 The Intended Usage (Safe)
A normal city administrator shutting off a single meter for a main break sends one HTTP POST request with one mutation.
```graphql
mutation ShutOffSingleMeter {
  setValveState(meterId: "MTR-10045", targetState: CLOSED) {
    status
    queuedAt
  }
}
```
