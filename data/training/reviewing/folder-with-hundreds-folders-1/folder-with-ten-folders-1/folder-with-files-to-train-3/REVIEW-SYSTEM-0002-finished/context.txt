# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** AegisForge Collaboration Portal
**Document Version:** 4.1.2 (FINAL)
**Classification:** CUI / ITAR RESTRICTED
**Domain:** Defense Industrial Base (DIB) / Supply Chain Logistics

## 1.0 Executive Summary
AegisForge is a centralized supply chain collaboration portal used by prime defense contractors and Tier-1/Tier-2 subcontractors. It facilitates the secure exchange of engineering blueprints, Bill of Materials (BOMs), and procurement schedules for next-generation aerospace platforms.

To comply with CMMC (Cybersecurity Maturity Model Certification) Level 3 and ITAR (International Traffic in Arms Regulations), the system is deployed entirely within AWS GovCloud. It utilizes a strict Zero Trust Network Access (ZTNA) model and exposes data to partner networks via a highly controlled Apollo GraphQL Supergraph.

## 2.0 Network Topology & Zero Trust Boundaries
The network assumes all incoming connections—even from cleared partner facilities—are untrusted until cryptographically verified at the application layer.

### 2.1 ZTNA Edge Ingress
* **Access Proxy:** Appgate SDP (Software Defined Perimeter) acts as the ingress controller. Partner engineers cannot even resolve the DNS of the API gateway until they establish an IPsec tunnel authenticated by their local endpoint management agent.
* **API Gateway:** An AWS API Gateway (GovCloud) receives HTTP/POST requests bound for the `/graphql` endpoint. 

### 2.2 GraphQL Supergraph (Compute Tier)
* **Federation Router:** An Apollo Router written in Rust handles the execution of incoming GraphQL queries. 
* **Subgraphs:** The router delegates queries to dedicated microservices (Go and Java) running in Amazon EKS:
  * `Project-Subgraph`: Manages broad project structures (e.g., "Project F-X").
  * `Component-Subgraph`: Manages the specific hardware parts and their states (Draft, Under Review, Published).
  * `Document-Subgraph`: Retrieves the actual binary blueprint files from S3.

## 3.0 Identity, Clearances, and Authorization
Identity relies on hardware-backed smartcards, mapped to strict Attribute-Based Access Control (ABAC).

### 3.1 Authentication (CAC/PIV to OIDC)
Users authenticate using their Department of Defense CAC (Common Access Card) or a partner-equivalent PIV card. PingFederate validates the hardware certificate and issues an OpenID Connect (OIDC) JWT.
* **Clearance Claim:** The JWT includes custom claims such as `clearance_level: "SECRET"` and `caveats: ["NOFORN"]` (No Foreign Nationals).
* **Vendor Claim:** The JWT includes the user's employer ID: `vendor_id: "VND-8819"`.

### 3.2 Publication State Machine (AuthZ Gate)
Subcontractors (`vendor_id`) are assigned to specific `Projects`. However, they are **strictly forbidden** from viewing `Components` or `Documents` related to that project if the item is in the `DRAFT` or `PENDING_REVIEW` state. They may only view data once the Government Contracting Officer explicitly transitions the state to `PUBLISHED`.

## 5.0 GraphQL Federation Supergraph (Apollo Schema)

### 5.1 Subgraph Type Definitions
```graphql
schema {
  query: Query
}

type Query {
  # Top-level entry points
  project(id: ID!): Project
  component(id: ID!): Component
}

# --- PROJECT SUBGRAPH ---

type Project @key(fields: "id") {
  id: ID!
  classification: String!
  codename: String!
  assigned_vendors: [String!]!

  # SECURE RESOLVER: Only returns Component IDs where state == 'PUBLISHED'
  published_components: [Component!]!

  # ALTERNATE RESOLVER (VULN A): Intended for internal PMs, but exposed globally.
  # It filters by `assigned_vendors`, but FAILS to filter by Component `state`.
  # This allows a subcontractor to traverse down into DRAFT components.
  components_in_progress: [Component!]!
}

# --- COMPONENT SUBGRAPH ---

type Component @key(fields: "id") {
  id: ID!
  project_id: ID!
  nomenclature: String!

  # State Machine: DRAFT -> PENDING_REVIEW -> PUBLISHED
  state: String! 

  # The associated CAD drawings and ITAR-restricted specs
  blueprints: [Blueprint!]!
}

# --- DOCUMENT SUBGRAPH ---

type Blueprint @key(fields: "document_id") {
  document_id: ID!
  filename: String!
  file_size_bytes: Int!
  mime_type: String!

  # Dynamically generated AWS GovCloud S3 Presigned URL (Valid for 15 mins)
  s3_download_url: String!
}
```

## 6.0 AWS GovCloud S3 Document Flow (The Impact)

### 6.1 Presigned URL Generation
AegisForge does not proxy heavy file downloads through the GraphQL router. Instead, it uses the **Valet Key Pattern**:
1. When a GraphQL query requests the `s3_download_url` field on a `Blueprint` object, the `Document-Subgraph` is invoked.
2. The `Document-Subgraph` checks the IAM role of the executing Lambda function.
3. It generates an AWS S3 Presigned URL using `sts:AssumeRole` and returns it to the user.

### 6.2 The Missing Defense-in-Depth
The `Document-Subgraph` **implicitly trusts** the upstream subgraphs. It assumes that if a user has successfully navigated the graph to request a `Blueprint`, the parent `Component` resolver has already verified the publication state and access rights.

## 8.0 Operational Reliability Addendum
### 8.1 Dispatch SLA and Capacity Planning
- Dispatch map refresh objective: p95 under 2.5 seconds for tenant-scoped fleet views.
- Batch query fan-out is capped per request to protect peak-hour dispatcher workflows.
- Capacity plans reserve additional headroom for weather-event traffic spikes.

### 8.2 Observability and Alerting
- API telemetry includes request volume, query latency, and cache effectiveness by endpoint.
- Kafka consumer lag is tracked per topic partition and surfaced to on-call dashboards.
- Nightly data-quality checks compare telemetry ingestion counts to active modem registry.

### 8.3 Change and Release Controls
- Schema migrations follow expand/contract rollout with tenant-safe backfill windows.
- Feature flags gate new dashboard polling behaviors before full deployment.
- Rollback runbooks require preserving geospatial index integrity and query-plan stability.
