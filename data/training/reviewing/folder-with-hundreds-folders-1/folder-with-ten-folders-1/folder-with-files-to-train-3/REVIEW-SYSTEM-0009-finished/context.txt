# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** NetLink Fiber CPE Provisioning Gateway
**Document Version:** 1.5.0 (FINAL)
**Classification:** CONFIDENTIAL / CPNI (Customer Proprietary Network Information)
**Domain:** Telecommunications / ISP / Residential Fiber

## 1.0 Executive Summary
NetLink Fiber provides Gigabit Fiber-to-the-Home (FTTH) services across multiple metropolitan areas. When a customer orders service, a field technician is dispatched to physically install and provision the Optical Network Terminal (ONT) and Wi-Fi router. 

To facilitate this, technicians use a mobile iPad application that communicates with the centralized CPE Provisioning Gateway. This REST API allows technicians to search for their assigned work orders, validate the fiber optic light levels, and bind the MAC address of the hardware to the customer's billing account.

## 2.0 Network Topology & Provisioning Flow
The architecture bridges the mobile field workforce with the core OSS/BSS (Operations Support Systems / Business Support Systems).

### 2.1 The Ingress Layer
* **Mobile App:** An iOS application deployed via Mobile Device Management (MDM).
* **API Gateway:** An Apigee edge proxy that handles rate limiting, JWT validation, and routing.

### 2.2 The Backend Services
* **Work Order Service:** A Spring Boot application connecting to a MySQL database that tracks installation appointments.
* **Network Controller:** A Python/Celery service that communicates via SNMP to the central office OLTs (Optical Line Terminals) to physically activate the fiber ports.

## 3.0 Identity, Roles, and Authorization
Customer Proprietary Network Information (CPNI) regulations strictly prohibit the unauthorized sharing of customer data, including who subscribes to the service and where they live.

### 3.1 Technician Authentication
Field technicians authenticate via Azure Active Directory (Azure AD), receiving a JWT that contains their employee ID and assigned regional zone (e.g., `zone: "US-NC-WAKEFOREST"`).

### 3.2 Dispatch Authorization Model (Intended)
The system is designed so that a technician should only see the names and addresses of customers on their specific daily dispatch route.

## 5.0 Database Schema (MySQL / Percona)
The OSS/BSS core uses a relational database to track all installation tickets. Notice the primary key structure and the presence of highly sensitive Customer Proprietary Network Information (CPNI).

```sql
-- Core Installation Tickets Table
CREATE TABLE work_orders (
    ticket_id INT AUTO_INCREMENT PRIMARY KEY, 

    assigned_tech_id VARCHAR(50), -- e.g., 'TECH-8821'
    status VARCHAR(20) DEFAULT 'PENDING',

    -- Highly Sensitive CPNI Data
    customer_first_name VARCHAR(100),
    customer_last_name VARCHAR(100),
    unlisted_phone_number VARCHAR(20),
    service_address VARCHAR(255),
    gate_or_security_code VARCHAR(50),
    latitude DECIMAL(10, 8),
    longitude DECIMAL(11, 8),

    mac_address_bound VARCHAR(17),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_assigned_tech ON work_orders(assigned_tech_id);
```
