Here is the twenty-second system, focusing on a critical failure in the Defense Industrial Base (DIB) sector. We are examining a Secure Document Vault API used for storing and retrieving classified manufacturing blueprints and supply chain attestations.

For the vulnerabilities, we are focusing on Pattern 4.4 (IaC State File Exposure) combined with Pattern 1.12 (Mass Assignment). This scenario demonstrates how an administrative endpoint intended for updating metadata on the vault’s underlying Infrastructure-as-Code (IaC) configuration is improperly secured. An attacker exploits a Mass Assignment vulnerability to inject a new cloud resource URL, which the application then uses in a file synchronization routine, leading to a Server-Side Request Forgery (SSRF) that exfiltrates the raw terraform.tfstate file—containing database credentials, internal IPs, and secret keys—to an external, attacker-controlled S3 bucket.

# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** Aegis Vault & DIB Configuration Manager
**Document Version:** 8.0.4 (FINAL)
**Classification:** CRITICAL DIB / CUI & ITAR SCOPE
**Domain:** Defense Industrial Base (DIB) / Classified Data Management / Cloud Security

## 1.0 Executive Summary
Aegis Vault is the central repository for controlled unclassified information (CUI) and International Traffic in Arms Regulations (ITAR) compliant data, including F-35 maintenance protocols and submarine manufacturing schematics. The system runs on a highly secure, isolated AWS GovCloud environment.

To maintain compliance and enable continuous deployment, the vault's cloud infrastructure (VPC, databases, KMS keys) is managed entirely via Terraform. A custom API endpoint exists for the DevSecOps team to update the location of the central Terraform state file (terraform.tfstate) before initiating new deployments or syncs.

## 2.0 Comprehensive Network Topology & Configuration Management
The architecture strictly separates the API plane (HTTP requests) from the backend configuration plane (file synchronization and state management).

### 2.1 The Ingress Layer & API Gateway
* **Cloud WAF:** Fronts the API, blocking common injection attacks.
* **API Gateway (Go-lang):** Handles routing and token validation. It exposes two classes of endpoints: /api/v1/documents (for standard users) and /api/v1/admin/config (for DevSecOps team only).

### 2.2 The Configuration Service (The Flaw)
* **ConfigSync Service (Python Flask):** A microservice that manages the deployment metadata. It receives configuration updates and performs scheduled synchronization tasks, including periodically pulling the terraform.tfstate file from a secure, internal S3 bucket (s3://aegis-iac-state-internal).
* **The Execution Context:** The ConfigSync Service runs on a privileged AWS EC2 instance with an IAM role that possesses s3:GetObject and s3:PutObject permissions for all internal GovCloud buckets.

## 3.0 Identity, Access, and IaC State
Access to the configuration endpoints is restricted to highly privileged DevSecOps engineers.

### 3.1 Role-Based Access Control (RBAC)
User tokens contain a role claim. The Go-lang API Gateway enforces that only users with the DEVSECOPS_ADMIN role can access the /admin/config endpoints.

### 3.2 The IaC State File
The terraform.tfstate file contains plaintext secrets, including:
AWS access keys for a legacy account.
PostgreSQL database username/passwords.
Internal VPC IP CIDR blocks and Security Group IDs.
The raw passphrase for the KMS encryption key.
Exfiltrating this file means total compromise of the entire DIB network infrastructure.
## 4.0 Known System Debt & Theoretical Attack Surfaces
*Internal Security Engineering Note: The Python Flask framework's default ORM configuration auto-binds incoming JSON to the Config database model if the field names match. The ConfigSyncService uses a single monolithic JSON payload for both security-sensitive settings and benign settings (like deployment region). Tracked as RISK-DIB-011.*

### 4.1 Vulnerability A: Mass Assignment to IaC State File Exfiltration (SSRF)
**Taxonomy Pattern:** 4.4 (IaC State File Exposure) & 1.12 (Mass Assignment)
**Sub-system:** ConfigSync Service (`POST /api/v1/admin/config/update`)

**The Deep Architectural Flaw:**
This attack chains two vulnerabilities: Mass Assignment and a logical flaw in a scheduled job.

1.  **Mass Assignment (Pattern 1.12):** The Python Flask endpoint is designed to accept benign configuration updates (like deployment_region). The code uses a to_dict() operation that maps the entire incoming JSON request body directly onto the Config database object, including sensitive fields the user should not be able to write, such as internal_state_url.
2.  **IaC State Exfiltration via SSRF (Pattern 4.4):** The ConfigSyncService has a scheduled job that is hardcoded to always synchronize the state file by executing s3.sync_objects(source=Config.internal_state_url, destination=Config.external_sync_url). By exploiting the Mass Assignment flaw, an attacker can overwrite Config.internal_state_url to point to the secure s3://aegis-iac-state-internal bucket, and simultaneously overwrite Config.external_sync_url to point to their own external S3 bucket (s3://attacker-exfil-bucket). The next scheduled sync job will execute the attacker's command.

**The Exploitation Path:**

1.  An attacker, a standard developer, registers a low-privilege account and obtains a restricted JWT.
2.  RBAC Bypass: The attacker realizes they cannot access the /admin/config path because the Go-lang API Gateway blocks them. They must first find a way to escalate their privileges.
3.  Privilege Escalation via Parameter Tampering (Mass Assignment): The attacker discovers a separate, lower-privileged endpoint, /api/v1/admin/config/metadata, that does accept their token. They send a PUT request to this endpoint with a malicious payload: {"role": "DEVSECOPS_ADMIN"}. Due to an assumed Mass Assignment flaw in that endpoint, their token's role claim is overwritten in the session context (or a profile database) to DEVSECOPS_ADMIN.
4.  The Configuration Overwrite: Now holding the elevated DEVSECOPS_ADMIN role, the attacker calls the target API: POST /api/v1/admin/config/update. The attacker sends a Mass Assignment payload that overwrites the internal file synchronization paths:
*   internal_state_url is set to the target's secure state file: s3://aegis-iac-state-internal/terraform.tfstate.
*   external_sync_url is set to the attacker's exfiltration bucket: s3://attacker-exfil-bucket/stolen-state-file.
5.  The Execution: The Flask ORM silently updates the Config table with the attacker's malicious URLs. Minutes later, the scheduled ConfigSyncService wakes up and executes the synchronization command, which runs under the highly privileged EC2 IAM role. The Terraform state file is copied from the secure internal location to the attacker's public S3 bucket.

## 5.0 DIB Configuration Schema (PostgreSQL)
The database stores the configuration paths used by the internal synchronization cron job. The flaw is that internal_state_url and external_sync_url are writable by the Mass Assignment vulnerability.

```sql
-- Single-Row Configuration Table
CREATE TABLE deployment_config (
config_id INT PRIMARY KEY DEFAULT 1,
deployment_region VARCHAR(50), -- Benign field
-- Synchronization Fields (THE VULNERABLE TARGETS)
internal_state_url VARCHAR(255) NOT NULL, -- e.g., s3://aegis-iac-state-internal/terraform.tfstate
external_sync_url VARCHAR(255) NOT NULL,  -- e.g., s3://internal-backup-external

sync_interval_minutes INT DEFAULT 60,
last_updated TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```
