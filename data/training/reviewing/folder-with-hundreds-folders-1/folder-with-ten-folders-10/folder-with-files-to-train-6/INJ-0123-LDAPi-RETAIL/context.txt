# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** RewardCore Loyalty API
**Document Version:** 1.7.0 (FINAL)
**Classification:** SENSITIVE
**Domain:** Retail / Loyalty Programme
**Training Example ID:** INJ-0123

## 1.0 Executive Summary
RewardCore Loyalty API is a retail / loyalty programme platform with a REST API. The platform
uses Active Directory (LDAP) for loyalty member authentication and account lookup. The `/api/v3/orders`
endpoint filters loyalty orders by member username using an LDAP directory query. Additionally,
a legacy SQL path remains active for order data retrieval from the relational database.
Input sanitization is inconsistent across the codebase.

## 2.0 Architecture
- **API Layer:** Node.js / Express REST API
- **Directory Services:** Active Directory (LDAP) — loyalty member authentication and lookup
- **Database:** PostgreSQL (via legacy SQL path)
- **Auth:** JWT Bearer tokens
- **Known Debt:** Older endpoint `/api/v3/orders` passes `filter` parameter directly to LDAP query and SQL query without sanitization

## 3.0 Vulnerable Endpoint
```
GET /api/v3/orders?filter=<user_input>
Authorization: Bearer <JWT>
```

**Backend Code Snippet (LDAP authentication path):**
```javascript
// Node.js — LDAP filter constructed from user input without escaping
// Note: filter parameter is interpolated directly into LDAP search filter
const ldapFilter = `(&(objectClass=user)(cn=${req.query.filter}))`;
ldapClient.search('dc=rewardcore,dc=local', { filter: ldapFilter }, (err, res) => { ... });
```

**Legacy Code Snippet (SQL path — active on same endpoint):**
```javascript
// Node.js — raw SQL query construction (legacy path)
const query = `SELECT * FROM orders WHERE filter = '${req.query.filter}'`;
db.execute(query, (err, results) => { ... });
```

## 4.0 Injection Payload
The following input was recorded in the penetration test:
```
filter=admin)(&(password=*))
```

## 6.0 Misconfiguration Notes
- Over-privileged directory binding: service account has read access to all directory attributes
- Verbose error messages enabled in staging (and leaked to production accidentally)
- No WAF or input validation middleware on legacy endpoints

## 7.0 Known Risk
- **RISK-INJ-123:** Endpoint `/api/v3/orders` passes `filter` parameter directly to LDAP search filter without special character escaping.
  A legacy SQL path on the same endpoint also uses raw string concatenation.
