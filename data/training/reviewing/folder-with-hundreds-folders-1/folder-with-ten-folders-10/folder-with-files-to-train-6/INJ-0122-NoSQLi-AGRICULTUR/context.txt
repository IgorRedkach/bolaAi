# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** HarvestIQ IoT Platform
**Document Version:** 4.7.0 (FINAL)
**Classification:** SENSITIVE
**Domain:** Agriculture / Precision Farming
**Training Example ID:** INJ-0122

## 1.0 Executive Summary
HarvestIQ IoT Platform is a agriculture / precision farming platform with a REST API backed by MongoDB.
The platform exposes search and filter endpoints that accept user-supplied parameters.
Input sanitization is inconsistent across the codebase due to a mix of raw query
construction and ORM usage.

## 2.0 Architecture
- **API Layer:** Node.js / Express REST API
- **Database:** MongoDB / document store — primary data store
- **Auth:** JWT Bearer tokens
- **Known Debt:** Older endpoint `/api/v3/products` accepts JSON-parsed query parameters without operator sanitization

## 3.0 Vulnerable Endpoint
```
GET /api/v3/products?username=<user_input>
Authorization: Bearer <JWT>
```

**Backend Code Snippet (MongoDB query path):**
```javascript
// Node.js — MongoDB query using user-supplied parameter directly
// Note: username parameter is passed to find() without sanitization or operator stripping
const username = JSON.parse(req.query.username);   // JSON parsing allows object operators
const products = await db.collection('products').find({ username: username }).toArray();
```

**Legacy Code Snippet (SQL path — present on same endpoint due to dual-backend migration):**
```javascript
// Node.js — raw SQL query construction (VULNERABLE)
// Note: legacy SQL path still active on this endpoint
const query = `SELECT * FROM products WHERE username = '${req.query.username}'`;
db.execute(query, (err, results) => { ... });
```

## 4.0 Injection Payload
The following input was recorded in the penetration test:
```
username={ "$gt": "" }
```

## 6.0 Misconfiguration Notes
- Over-privileged DB account: application connects as `db_owner` instead of a restricted role
- Verbose error messages enabled in staging (and leaked to production accidentally)
- No WAF or input validation middleware on legacy endpoints

## 7.0 Known Risk
- **RISK-INJ-122:** Endpoint `/api/v3/products` does not sanitize MongoDB query operators.
  JSON-parsed query parameters allow `$gt`, `$ne`, `$where`, and `$regex` operator injection.
  A legacy SQL path on the same endpoint also uses raw string concatenation.
