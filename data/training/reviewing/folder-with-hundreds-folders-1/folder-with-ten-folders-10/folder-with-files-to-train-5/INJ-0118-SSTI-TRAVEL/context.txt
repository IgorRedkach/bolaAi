# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** SkyPort Global Distribution
**Document Version:** 1.4.0 (FINAL)
**Classification:** SENSITIVE
**Domain:** Travel / GDS
**Training Example ID:** INJ-0118

## 1.0 Executive Summary
SkyPort Global Distribution is a travel / gds platform with a REST API. The platform uses a
Jinja2/Nunjucks template engine to render dynamic content in several endpoints. Search and filter
parameters are accepted from client requests and processed by the backend.
Input sanitization is inconsistent across the codebase due to a mix of raw query
construction and ORM usage.

## 2.0 Architecture
- **API Layer:** Node.js / Express REST API
- **Template Engine:** Jinja2 (Python legacy service) / Nunjucks (Node.js active service)
- **Database:** PostgreSQL (via Sequelize ORM)
- **Auth:** JWT Bearer tokens
- **Known Debt:** Older endpoint `/api/v2/accounts` uses string concatenation for query building

## 3.0 Vulnerable Endpoint
```
GET /api/v2/accounts?filter=<user_input>
Authorization: Bearer <JWT>
```

**Backend Code Snippet (legacy accounts service):**
```javascript
// Node.js — legacy accounts endpoint (migrated from Python/Jinja2 service)
// Note: filter parameter is interpolated directly into query without sanitization
const query = `SELECT * FROM accounts WHERE filter = '${req.query.filter}'`;
db.execute(query, (err, results) => { ... });
```

**Template engine integration (accounts response renderer):**
```javascript
// Nunjucks template rendering — user-supplied data flows into template context
const template = nunjucks.renderString(
  'Welcome, {{ filter }}! Your accounts: {{ accounts | safe }}',
  { filter: req.query.filter, accounts: results }
);
```

## 4.0 Injection Payload
The following input was recorded in the penetration test:
```
filter={{7*7}}
```

## 6.0 Misconfiguration Notes
- Over-privileged DB account: application connects as `db_owner` instead of a restricted role
- Verbose error messages enabled in staging (and leaked to production accidentally)
- No WAF or input validation middleware on legacy endpoints

## 7.0 Known Risk
- **RISK-INJ-118:** Endpoint `/api/v2/accounts` uses raw string concatenation.
  Parameterized queries are used in newer endpoints but this one was missed in the migration.
  The endpoint also flows user input into Nunjucks template context without escaping.
