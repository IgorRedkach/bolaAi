# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** MetroPulse Traffic Orchestration (Salesforce-Integrated)
**Document Version:** 4.0.0 (FINAL)
**Classification:** SENSITIVE
**Domain:** Smart City / Traffic Management
**Platform:** Salesforce Lightning / Aura Framework
**Training Example ID:** SF-0254

## 1.0 Executive Summary
MetroPulse Traffic Orchestration is a smart city / traffic management platform built on Salesforce Lightning Experience.
The front-end uses Aura Components that communicate with Apex Controllers via the Salesforce
Aura Framework's `c.ControllerName.methodName` call pattern. Authorization is expected to be
enforced through Salesforce sharing rules (OWD, Role Hierarchy, Sharing Rules) AND explicitly
in Apex controller code using `WITH SECURITY_ENFORCED` or manual ownership checks.

## 2.0 Architecture Overview
- **Front-End:** Salesforce Lightning Aura Components (LWC migrated to Aura)
- **Middle Layer:** Apex Controllers called via Aura Action Framework
- **Data Layer:** Salesforce Objects with standard and custom fields
- **Auth:** Salesforce Session ID (Bearer token), OWD = Private on Lead object

## 3.0 Salesforce Object Schema
```sql
-- Lead Object (Standard + Custom Fields)
Lead (
  Id           VARCHAR(18) PRIMARY KEY,   -- Salesforce record ID
  Name         VARCHAR(255),
  OwnerId      VARCHAR(18),               -- Links to User object
  AccountId    VARCHAR(18),               -- Parent account
  SensitiveData__c VARCHAR(500),          -- Custom field: sensitive PII/business data (restricted FLS)
  InternalNotes__c  TEXT,                 -- Custom field: internal review notes (restricted FLS)
  IsDeleted    BOOLEAN DEFAULT FALSE
)
```

## 4.0 Apex Controller Implementation
```apex
public class LeadController {
    @AuraEnabled
    public static List<Lead> getLeadDetails(String leadId, List<String> fields) {
        // Note: class declaration does not include 'with sharing'
        // No ownership or tenancy check present in WHERE clause
        // fields parameter from client is used directly in SELECT — no FLS check per field
        String selectFields = String.join(fields, ', ');
        return [Lead]Database.query(
            'SELECT ' + selectFields + ' ' +
            'FROM Lead ' +
            'WHERE Id = :' + leadId
        );
    }
}
```

## 5.0 Behavioral Notes

The Apex controller `c.LeadController.getLeadData` accepts two client-supplied parameters:
- `leadId` — used directly in SOQL WHERE without ownership validation
- `fields` — a list of field names supplied by the client, concatenated directly into the SELECT clause

The server does not validate that the calling user has Field Level Security (FLS) access to each
field in the `fields` array. Custom fields like `SensitiveData__c` and `InternalNotes__c` are
included in the response if the client lists them in the `fields` array, regardless of the caller's FLS permissions.

## 7.0 Sharing Rule Configuration
```
Lead OWD: Private
Sharing Rules: Users can access records they own or have been explicitly shared with them.
Apex Controller Declaration: "public class LeadController" (WITHOUT "with sharing")
Field Level Security: SensitiveData__c and InternalNotes__c are restricted to Admin profile only.
```

## 8.0 Known Risks
- **RISK-SF-254:** Controller declared without `with sharing`. Sharing rules not enforced by Apex layer.
- **RISK-SF-255:** No ownership check in SOQL WHERE clause. Any caller-supplied leadId is accepted.
- Client-supplied `fields` array is concatenated directly into SELECT without FLS validation per field.
