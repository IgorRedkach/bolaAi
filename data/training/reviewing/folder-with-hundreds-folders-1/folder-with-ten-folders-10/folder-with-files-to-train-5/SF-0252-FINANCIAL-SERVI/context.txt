# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** NexaBank Open Finance API (Salesforce-Integrated)
**Document Version:** 4.3.0 (FINAL)
**Classification:** SENSITIVE
**Domain:** Financial Services / Retail Banking
**Platform:** Salesforce Lightning / Aura Framework
**Training Example ID:** SF-0252

## 1.0 Executive Summary
NexaBank Open Finance API is a financial services / retail banking platform built on Salesforce Lightning Experience.
The front-end uses Aura Components that communicate with Apex Controllers via the Salesforce
Aura Framework's `c.ControllerName.methodName` call pattern. Authorization is expected to be
enforced through Salesforce sharing rules (OWD, Role Hierarchy, Sharing Rules) AND explicitly
in Apex controller code using `WITH SECURITY_ENFORCED` or manual ownership checks.

## 2.0 Architecture Overview
- **Front-End:** Salesforce Lightning Aura Components (LWC migrated to Aura)
- **Middle Layer:** Apex Controllers called via Aura Action Framework
- **Data Layer:** Salesforce Objects with standard and custom fields
- **Auth:** Salesforce Session ID (Bearer token), OWD = Private on Account object

## 3.0 Salesforce Object Schema
```sql
-- Account Object (Standard + Custom Fields)
Account (
  Id           VARCHAR(18) PRIMARY KEY,   -- Salesforce record ID
  Name         VARCHAR(255),
  OwnerId      VARCHAR(18),               -- Links to User object
  AccountId    VARCHAR(18),               -- Parent account
  SensitiveData__c VARCHAR(500),          -- Custom field: sensitive PII/business data
  InternalNotes__c  TEXT,                 -- Custom field: internal review notes
  IsDeleted    BOOLEAN DEFAULT FALSE
)
```

## 4.0 Apex Controller Implementation
```apex
public class AccountController {
    @AuraEnabled
    public static List<Account> getAccountDetails(String accountId, List<String> fields) {
        // Note: class declaration does not include 'with sharing'
        // No ownership or tenancy check present in WHERE clause
        return [Account]Database.query(
            'SELECT Id, Name, OwnerId, SensitiveData__c, InternalNotes__c ' +
            'FROM Account ' +
            'WHERE Id = :' + accountId
        );
    }
}
```

## 5.0 Behavioral Notes

The Apex controller `c.AccountController.getAccounts` accepts an `accountId` parameter from the
client-side Aura component. The server processes whichever `accountId` value the client supplies.
A user with a valid session for their own Account record can substitute a different `accountId` in
the Aura request payload to extend their session's access scope beyond what they legitimately own.
The controller does not call `UserInfo.getUserId()` in its WHERE clause.

## 7.0 Sharing Rule Configuration
```
Account OWD: Private
Sharing Rules: Users can access records they own or have been explicitly shared with them.
Apex Controller Declaration: "public class AccountController" (WITHOUT "with sharing")
```

## 8.0 Known Risks
- **RISK-SF-252:** Controller declared without `with sharing`. Sharing rules not enforced by Apex layer.
- **RISK-SF-253:** No ownership check in SOQL WHERE clause. Any caller-supplied accountId is accepted.
- Client-supplied `accountId` is directly interpolated into SOQL without validation.
