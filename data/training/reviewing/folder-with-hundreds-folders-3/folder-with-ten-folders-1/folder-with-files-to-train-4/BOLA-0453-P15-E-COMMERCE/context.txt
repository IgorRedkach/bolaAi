# ENGINEERING ARCHITECTURE SPECIFICATION
**System Name:** ShopGrid Marketplace API
**Document Version:** 2.2.0 (FINAL)
**Classification:** SENSITIVE
**Domain:** E-Commerce / Marketplace
**Architecture:** GraphQL storefront + microservices
**Training Example ID:** BOLA-0453

## 1.0 Executive Summary
ShopGrid Marketplace API is a e-commerce / marketplace platform with a REST API. Resources are partitioned
by `tenant_id` and ownership is tracked via `owner_id`. The API uses JWT authentication
where the token encodes `sub` (user ID) and `tenant_id`.

## 2.0 Architecture
- **API:** REST (/api/v3/resources endpoints)
- **Auth:** OAuth2 JWT with `sub` and `tenant_id` claims
- **Database:** PostgreSQL with logical tenant partitioning
- **Pattern under test:** 1.5 — Multi-tenant / cross-tenant access

## 3.0 Database Schema
```sql

-- Resource table
CREATE TABLE resources (
    resource_id    VARCHAR(50) PRIMARY KEY,
    owner_id         VARCHAR(50) NOT NULL REFERENCES users(user_id),
    tenant_id        VARCHAR(50) NOT NULL,
    status           VARCHAR(20) DEFAULT 'active',
    sensitive_data   TEXT,
    created_at       TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_resource_tenant ON resources(tenant_id);
-- NOTE: Application code does NOT use tenant_id in authorization checks

```

## 4.0 Vulnerability Context
**Pattern:** 1.5 — Multi-tenant / cross-tenant access (BOLA)

The `GET/PATCH/DELETE /api/v3/resources/:id` endpoint accepts a `resource_id` in the URL path.
The backend handler queries the database by ID only, without filtering by `owner_id` or `tenant_id`.
An authenticated user from `ORG-4786` can access objects owned by `ORG-6D6E`.

_Specific exploitation for Pattern 1.5:_ Token from `ORG-4786` passes `tenantId=ORG-6D6E` as a query parameter. Server trusts client-supplied tenant.
